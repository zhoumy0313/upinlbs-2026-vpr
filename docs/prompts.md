# 分阶段交给本地 Codex 的指令

每次只发当前阶段。每阶段结束先核对输出，不要直接连续执行全项目。

## P0：接续已有环境
读取 PLAN.md、AGENTS.md 和 configs/protocol.yaml。保留已有 SSH、FlClash 和 Codex 设置；检查当前 Ubuntu 的 CPU、内存、磁盘、GPU/驱动、Python、网络与 Codex 状态。在独立虚拟环境内跑通本包单元测试及官方 CosPlace toy 示例；有 GPU 才选择兼容 GPU 版 PyTorch，否则用 CPU。暂不训练、不读最终测试结果、不修改驱动。提交环境报告、实际命令、日志和输入输出说明。

## P1：数据与评测
建立两个数据集的 manifest、对齐检查及冻结划分。用 VPR_Tutorial 原作者代码核对 Gardens Point GThard/GTsoft，核对 Nordland-Part 的对应帧；不要伪造 UTM 坐标。完成图像可读性、顺序、正样本集合、Recall 和缓存一致性检查。Gardens Point 只做数据检查及自检索，不查看夜间跨域测试指标。报告例图、测试和协议解释。

## P2：冻结特征与开发集
适配 CosPlace R18/512 和 DINOv2 ViT-S14 CLS/384，编码器只推理。保存带图像ID和配置指纹的描述子。只评测 Nordland train/validation，输出 R@1/5/10、四格互补性、纠错/误伤机会和真实单图延迟。检查是否有足够复核收益；不要调整最终测试。核查最相关的 SU、选择性匹配和 SMR 论文，逐项记录与本方案的区别。

## P3：选择器与消融
按协议实现五维 A-only 特征、两个逻辑回归头以及验证集预算门限。实现 A-only、B-only、随机触发、分数间隔、同特征错误预测器、收益选择器和去误伤头消融。文献比较方法须先核对原公式/代码。只用 train/validation 拟合与选门限；检查门控阶段完全不读取 B 或真值。保存参数、阈值、消融和解释。

## P4：冻结后的最终评测
经人工确认后记录 commit、配置哈希、模型和清单，冻结方案。统一评测 Nordland 留出段与 Gardens Point；报告所有结果、实际复核率、纠错/误伤数。实测在线 batch=1 路径，门控后才运行 B；缓存耗时不得算模型推理时间。输出论文图表及失败案例；不以最终测试结果调参。

## P5：写作与审计
只从冻结实验产物生成论文表格和论述，先完成方法及实验，再写引言和摘要。使用已核实的2026会议模板；当前 paper/main.tex 仅是 IEEE 风格工作骨架，不是已核实的官方模板。核对引用、AI披露、作者、页数和每个结论的证据。未实测内容保留 TODO，不生成假数据，不自动投稿。
