## 1. 现有工程的真实起点与研究问题

### 1.1 仓库已有的成果（只读历史基线）

现有 P0–P5 已完成：Ubuntu 环境与官方 CosPlace toy、Gardens Point 和 Nordland 数据审计、CosPlace/DINOv2/EigenPlaces 冻结模型推理、第一轮监督收益门控、对照/消融、冻结后的结果、实际在线耗时、独立数字校验及英文 5 页工作稿。

现有数据中的**原始 R@1，严禁改写**：

| 数据与现有协议 | CosPlace A | EigenPlaces B | 25%验证预算的收益门控 | 测试实际调用 B |
|---|---:|---:|---:|---:|
| Nordland 原留出段（650 查询，±5 帧） | 14.15% | 10.00% | 10.31% | 78.92% |
| Gardens Point 夜间（200 查询，严格对应帧） | 34.50% | 36.00% | 34.50% | 15.50% |

原留出段 A/B Top-1 的纠错机会 17、误伤机会 44、两者都错 541；因此完美选择 A/B Top-1 的 Oracle R@1 也仅有 **16.77%**，只能比 A 提高 **2.62 个百分点**。这不是新方法的预测成绩，而是旧策略类型的上限。

同一段 CosPlace 的 R@5 = 23.54%、R@10 = 30.62%。这说明**重排已有候选**理论空间大于简单 A/B Top-1 选择，但 R@10 只是该候选集合重排的上限，不是预期能达到的成绩。

开发段到留出段大幅下降（CosPlace 在旧验证段 71.33% → 原留出段 14.15%），需优先核对真值对齐、重复帧、图像区域与分布变化，**不可未审即认定下降完全由“domain shift”导致**。

### 1.2 新一轮研究问题

> 对跨光照/跨季节视觉地点识别，单帧编码器的真实正样本经常不在第 1 名。能否利用**已知图库顺序与在线当前/历史查询帧**构造时序一致性的候选重排序，在已有强时序基线之外得到可复现的精度或精度—计算成本改善？何时自适应机制优于固定窗口/固定融合？

优先方向：**因果时序匹配（causal temporal matching）与候选重排序**，而不是继续把“运行第二编码器与否”当作主要方法。双模型 RRF/静态融合用作低成本筛选对照，不应预设就是创新。

### 1.3 本轮研究不能做的主张

- 不能宣称“首次引入时序匹配”，SeqSLAM 已研究；不能宣称“首次选择性相信时序”，SMR 已研究。
- 不能声称 VPR 排名结果等同于米级位置、精确位姿、SLAM 回环已闭合或真实机器人部署。
- 不能将现有 Nordland 留出段/Gardens Point 重新视为未见测试：它们的结果已经被团队看过。
- 如果自适应方法没有超过固定窗口等强基线，不能仅凭优于 CosPlace 单帧就声称新方法的创新有效。

## 4. G2：复现强而简单的改进基线（无论文创新声明）

**目的**：用现成描述子首先验证“候选融合”和“过去查询帧的时序信息”是否有实际价值。所有参数只在 Nordland train/validation 研究，原留出段不作为方法筛选依据。

### G2.1 单图与融合参考

在相同数据、预处理、正样本和有效查询集合下实现：

- `A-only`: CosPlace 单帧，原描述子/分数；
- `B-only`: EigenPlaces 单帧；另外保留 DINOv2 负结果；
- `RRF(A,B)`: 两模型每张图库图的排名做倒数排名融合，明确候选全集、名次从 1 计、平滑常数 `k=60` 作为默认，必要时只用验证集选择少量备选；
- `Fixed score fusion(A,B)`: 归一化后分数静态融合（归一化方式必须说明，不得在测试上拟合统计参数）；
- 若双模型融合并无开发增益，停止这一路复杂化，保留它作为负对照。

RRF、分数加权均为既有基线；**不能把它们单独写成新算法**。

### G2.2 因果时序匹配基线（优先方向）

对连续查询流 `q_t`，数据库参考帧 `d_j`，冻结 CosPlace 产生分数矩阵：

\[
S(t,j)=z_A(q_t)^\top z_A(d_j).
\]

只使用当前与过去 `L` 个查询：

\[
T_t(j)=\max_{v\in\mathcal V}\frac{1}{L}\sum_{\ell=0}^{L-1}S\bigl(t-\ell,\,j-\mathrm{round}(v\ell)\bigr).
\]

这里 `v` 表示两次巡航采样速度的**相对参考帧步进**，不涉及真实 GPS；任一取样越界就将整条候选轨迹判无效，不应把缺失项平均或视为零。所有窗口里的历史查询必须来自**同一连续运行与同一划分区段**。最前面的不足 `L` 帧需标记暖机，主指标对所有方法使用共同有效查询集合；同时报告完整流的启动表现。

先固定并比较：

- `L ∈ {1,3,5,9}`；`L=1` 必须与单帧基线完全一致；
- `v ∈ {0.8,1.0,1.2}`，默认相同运动方向；如果参考序列方向不明，在开发集核对顺序并留下依据，而不是用测试 GT 决定方向；
- `fixed_temporal`: 仅使用 `T_t(j)` 重排序；
- `fixed_blend`: 使用预先定义的单帧与时序分数归一化，固定权重 `λ ∈ {0,0.25,0.5,0.75,1}`；
- 视资源情况，补充 `SeqSLAM-inspired` 或直接可运行的经典 SeqSLAM 匹配对照。**若没有严格按原作者算法和预处理复现，只能写 SeqSLAM-inspired，不能写 official SeqSLAM reproduction。**

所有参数选择在验证集完成，记录所有测试过的组合。不要无限制搜索速度、窗口和权重直到“碰到高分”。

### G2.3 数据/因果检查（必须自动化）

加入至少以下单元与集成测试：

1. `L=1` 与 A-only 排名/Recall 一致；
2. 同一查询流顺序固定，时间窗口永不读取 `q_{t+1}` 等未来帧；
3. 各 train/val/test 边界清空状态，不混用缓冲段查询；
4. 窗口索引越界的路径处理一致，不在错误帧上默默截断；
5. 禁止读取真值/正确标签/文件名中的位置 ID 来生成在线路径和权重；
6. 特征缓存行与 `image_id` 一一对应，重排 manifest 不改变评价；
7. 独立小样本手工计算 `T_t(j)` 与程序结果一致；
8. 用打乱过去查询帧的负对照检验时序收益是否确实来自顺序信息；
9. 所有对比在完全相同的有效查询集合上计算 R@K；
10. GPU/CPU、缓存模拟与真实查询重放结果在预声明精度范围内一致。

### G2 决策门槛（不要硬编码“必须涨分”）

- **优先条件**：固定时序在开发验证集相较 CosPlace 单帧有可信的错误减少；其改善不能只来自改变评价容差、筛选样本或误用 GT。还要与“固定窗口、固定融合”本身比较。
- 如果固定时序不改善，检查数据对齐和速度假设；完成**一次**有界的修正实验。仍无明显信号时进入 B 备选（候选融合或局部重排序），不在同样的想法上反复试数十套参数。
- 如果 RRF/候选融合改善而时序无效，记录“转方向 B”及原因，主线改为候选级融合与稳定性，仍需比最强**简单融合**有额外改进才可主张方法贡献。
- 如果两条线都无有效研究空间，停止添加算法，保留完整负结果，考虑实证分析稿；不能制造提升。

**G2 输出**：开发集强基线表、`L/λ/v` 敏感性、实际错误图像与因果测试、`G2_DECISION.md` 中明确选择下一步唯一方法方向。确认后自动进入 G3。

## 5. G3：在强基线之上形成一个范围有限的改进方法

### G3.1 首选创新假设（有条件执行）

若固定时序有效，检验：**仅在当前单帧结果存在歧义、时序候选获得连续支持且支持足够一致时，才增加时序重排序权重；否则维持单帧或较保守融合。** 这避免无条件时序在反向运动、重复站场、序列对齐失败时的误伤。

这个思路必须被当作**待验证假设**，不能自动认定比 SMR 新颖。

示例表示（Codex 可据开发证据作**一次有记录的具体化**）：

\[
F_t(j)=(1-\lambda_t)\widehat S(t,j)+\lambda_t\widehat T_t(j),\qquad \lambda_t\in[0,1].
\]

`\widehat S`、`\widehat T` 是明确定义的、在在线查询当时可获取的可比分数；`λ_t` 可使用如下**不依赖真值**的统计：
- 单帧 Top-1/Top-2 分数差；
- 时序路径 Top-1/Top-2 支持差；
- 单帧与时序最佳参考帧的候选一致性；
- 最近历史查询的路径连续性。

实现优先从**固定规则、极少超参数**开始；如果需要监督小模型，只在 Nordland train 上拟合，val 选配置，且必须与同容量简单对照比较。不做大型模型训练。不让推理端使用真实地点 ID、参考位置 GT 或未来帧。

### G3.2 与 SMR 的具体差异审查

SMR 已根据时序处理的纠错/误伤预测每帧受益，且提供代码与已有多数据集实验。新方法若仅是“检测何时应该信任时序结果”，**可能缺乏足够新意**。务必在 `RELATED_WORK_MATRIX.md` 中说明候选区别：

- 在线输入是否相同、是否需要额外模型或历史错误标签？
- 是选择最终匹配、过滤匹配还是对 Top-K 候选进行连续路径重新评分？
- 对速度变化、路径歧义与启动窗口的处理是否有新的明确定义？
- 是否实现可测量的 **精度/耗时/参数量/跨域稳定性**增益？

条件允许时复用 SMR 官方仓库/固定提交与其代码许可证做对照。若因依赖、输入定义或资源限制无法公平运行，应诚实记录缺失和适配差异；不能自行发明一个同名“SMR 简化版”冒充官方成绩。

### G3.3 必须存在的消融

至少：

| 方法 | 用途 |
|---|---|
| A 单帧 | 必需弱基线 |
| A 固定时序窗口 | 必需强基线 |
| A 单帧 + 时序固定比例融合 | 必需简单对照 |
| 自适应时序完整法 | 候选提出方法 |
| 移除时间一致性输入 | 检查时序信息贡献 |
| 固定 `λ` 替换自适应 `λ_t` | 检查自适应贡献 |
| 移除候选一致性/歧义中的一个组件 | 检查机制必要性 |
| RRF / 候选融合（如果有效） | 同等输入成本的成熟基线 |

**如复杂自适应法不超过固定窗口，优先简化或缩小论文主张，不能增加十个模块继续“调到有效”。**

### G3.4 创新路线备选与停止规则

只允许如下选择：

- **路线 A（默认）**：因果时序 Top-K 重排序 + 小型自适应一致性机制；
- **路线 B（仅 A 开发失败时）**：双模型候选级排名/分数融合，研究在有限额外编码计算下的候选收益；但 RRF/线性融合本身不得称创新，要明确对它们额外解决什么问题；
- **路线 C（都失败）**：保留负结果/失效分析，更新实证论文而不是发布无证据的“新方法”。

每次转路线在 `DECISION_LOG.md` 中写：原因、已经试过的具体配置、所依据的**开发集**证据、为何没有借用最终测试结果。冻结测试之后禁止再转方向并以同一测试集重新写“独立提升”。

**G3 验收**：一份实测的开发数据主结果表、完整参数与消融、`METHOD_V2.md`（问题→数学定义→算法→复杂度→差异）、可复现代码和测试；冻结前确定最终只保留**一个论文方法主线**。

## 6. G4：研究冻结、独立测试与真实运行成本

### G4.1 严格区分三个测试角色

- **开发用**：Nordland 训练 1–600、验证 701–1000（按已核实 one-based ordinal，保留旧缓冲）；方法、窗口、融合权重均在这里选择。
- **已被看过的历史结果**：旧 Nordland 留出 1101–1750、Gardens Point night_right。可用于描述/兼容性比较，但**不能再称新方法盲测**。若再次运行，要写 `post_hoc/exploratory`，不以其最好成绩挑最终方法。
- **新独立评价（优先）**：St Lucia。先用 `gmberton/VPR-datasets-downloader` 的官方整理版检查下载体积、时间顺序、GPS/UTM 字段、图库与查询定义及来源许可，核对真正的正样本语义，然后再决定是否采用。其公开仓库提供 `st_lucia` 数据的 `rsync` 获取方式；仓库标注其为 test-only。见 https://github.com/gmberton/VPR-datasets-downloader 。

### G4.2 St Lucia 类数据的特殊评价规则

- **不同轨迹不要按图像帧序号直接对应**。采用经过验证的参考/查询位置元数据建立正样本（例如同一 UTM 坐标系下的距离阈值）；阈值先按该数据集官方协议，否则在读取测试指标前写明自定义主阈值并做预定义敏感性报告。

- 对查询无任何合格正样本的情况，明确做 closed-set 有正样本子集评估并报告排除的条目及原因，或单独设计开放集实验；不能悄悄删除以提高准确率。
- 数据若不是连续时间序列（被大幅抽稀、顺序丢失），时序方法可能并不适用；应报告这个不匹配，不要强行使用参考帧差来冒充真实运动时序。
- 如使用官方整理版 GPS 标签，引用原始数据集与整理/格式化论文。

### G4.4 正式实验表与运行测试

## 9. 科研诚信、复现与自动验收红线

### 9.1 不能牺牲评价可信度换成绩

- 不因看到最终测试而改变正样本容差、选择最优帧区段、过滤错误查询、重命名测试为验证。
- 不把缓存仿真速度称为 GPU 在线推理时间；不把几万个策略×轮次计时记录称为几万个独立测试样本。
- 不以 Oracle 上限替代方法真实结果；不把动态窗口借助未来帧称在线因果法。
- 不把固定时序方法带来的改善误记为自适应模块的创新。
- 不在小范围输入预处理失败时私下改变原 baseline 的图像分辨率、骨干网络和权重而保持其旧名字。
- 如果旧指标和新指标计算协议改变，必须在表头显式写清两个协议，禁止直接画同一柱状图比较。
- 不私自清除已有失败记录、修改实验日志退出码或重写冻结源代码后使用旧运行数据。

### 9.2 代码与系统安全

- 所有新增 Python 代码加入单元/集成测试。每个阶段至少执行一次既有测试套件，并报告回归。
- 下载第三方仓库/数据需记录 URL、commit/checksum、许可证、是否需要用户权限；对可能超过可用资源的下载先做体积评估。在 400GB 磁盘上至少保留合理空闲空间；建议**预估超过30GB的额外下载前停下来列出决策**，不要批量下载整套大型视觉数据。
- 保留 FlClash/SSH/Codex/API 令牌、机场订阅、私钥不变，不把敏感信息进入 Git、日志、论文。
- 未经用户批准不改系统驱动、不做全局 CUDA/ROS 重装，不执行破坏性文件删除、不向旧 `main` 强推。
- 需要科研伦理或版权/投稿授权的动作转成 `human_action_required`，其余可在当前项目授权范围内继续。

## 10. 时间优先级与自动决策（截止投稿前）

日期按目前 2026-10-10 起：

| 建议顺序 | 阶段 | 到此必须拿到的成果 |
|---|---|---|
| 10/10 晚 | G0 + G1 | 旧稿完整冻结、GT/Top-K 上限审计、文献差异 |
| 10/11 | G2 | RRF 与固定因果时序的可信开发结果；选择唯一有效路线 |
| 10/12 | G3 | 有界自适应方法与消融；冻结模型/GT/参数/代码 |
| 10/13 | G4 | 新独立测试或真实阻塞证据、在线计时、最终方法评判 |
| 10/14 | G5 | 新论文版本、数字证据映射、≤6 页完整 PDF、导师审阅材料 |
| 10/15 | 人类作者最终检查 | 签字/署名/投稿条件核对、按官方系统手动提交 |

**顺序与科研质量比日期更重要。** 如果一个环节未通过，不可因为赶日期直接用假数据补上。到了 G4/G5 不再新增一整套未验证的方法族；优先完成论文可审阅性。

自动选路规则：

```text
G0 保全原工程
  └─ G1 校验GT与错误/Oracle空间
       ├─ GT不可信 → 修复新协议，仅开发数据复核；保留旧版本
       └─ 可用 → G2（RRF + 固定因果时序）
                    ├─ 固定时序开发上有效 → G3A 小型自适应
                    ├─ 仅候选融合有效 → G3B 只研究候选级增益
                    └─ 都无可靠增益 → G3C 诚实的失败/机制研究
                              ↓
                  G4 冻结协议 → 新独立测试（若可用）
                              ↓
                  G5 新版论文 → 证据审查 → 交用户决定投稿
```

**探索预算原则**：不要通过无限测试获得“漂亮的”正结果。G2 有限网格；G3 只保留一个被开发证据支持的方法家族；G4 新独立测试一次冻结协议。再多的调参也不能改变最初盲测的身份。
